# Convolution Block 3 — LUT Optimization

## 1. Baseline vs. Reuse 16/32

| Metric | Baseline | Reuse 16/32 | Change |
|---|---:|---:|---:|
| Total Latency | 1.730 ms | 2.603 ms | +50.5% |
| Pipeline Latency | 1.175 ms | 2.048 ms | +74.3% |
| Pipeline Interval (cycles) | 117,505 | 204,814 | +74.3% |
| Weight Loading | ~0.553 ms | ~0.553 ms | No change |

Hardware reuse increased latency, but LUT utilization remained high. The next step was to reduce intermediate arithmetic bitwidth.

## 2. Narrow-Width MAC Accumulation

The original implementation used 32-bit integers for intermediate MAC accumulation, even though activations and weights were signed 8-bit values.

### Before

```cpp
int32_t channel_sum = 0;

for (int k = 0; k < 9; ++k) {
#pragma HLS UNROLL
    const ap_uint<8> raw =
        pkt.range(8 * k + 7, 8 * k);

    const ap_int<8> x = (ap_int<8>)raw;
    const int32_t w =
        (int32_t)weights[k][ic * CONV3_2_OUT_C + oc];

    channel_sum += (int32_t)x * w;
}
```

### After

```cpp
// (heewon) Narrow-width MAC accumulation
ap_int<19> channel_sum = 0;

CONV3_2_REUSE_MAC9:
for (int k = 0; k < 9; ++k) {
#pragma HLS UNROLL

    const ap_uint<8> raw =
        pkt.range(8 * k + 7, 8 * k);

    const ap_int<8> x = (ap_int<8>)raw;
    const ap_int<8> w =
        (ap_int<8>)weights[k][ic * CONV3_2_OUT_C + oc];

    channel_sum += x * w;
}
```

A signed 8-bit multiplication requires up to 16 bits. The maximum positive sum of nine products is:

\(9 \times 128 \times 128 = 147,456\)

This fits within the range of a signed 19-bit accumulator.

**Change:** `int32_t` → `ap_int<19>`

## 3. Narrow-Width Partial Sums

The partial sums and phase accumulator were also narrowed.

### Before

```cpp
int32_t partial[32];
int32_t phase_sum = 0;
```

### After

```cpp
ap_int<19> partial[32];
ap_int<24> phase_sum = 0;
```

Each `partial` stores the sum of nine signed INT8 products, requiring 19 bits.

The `phase_sum` accumulates 32 partial sums:

\(19 + \log_2(32) = 24\text{ bits}\)

| Variable | Before | After |
|---|---|---|
| Channel sum | `int32_t` | `ap_int<19>` |
| Partial sum | `int32_t` | `ap_int<19>` |
| Phase sum | `int32_t` | `ap_int<24>` |

The final accumulation and bias addition must still use sufficient bitwidth to preserve correctness.

## 4. Weight Banking

Weight banking was applied to further reduce LUT utilization.

- LUT utilization decreased significantly.
- BRAM consumption increased and exceeded the available hardware budget.

The result showed a trade-off between LUT usage and BRAM consumption. Further memory restructuring is needed to reduce LUT usage while remaining within the BRAM budget.
